# 模板模型与报价验收 · 2026-11-10

在本机用 Chrome 打开真实的 `/admin/templates` 和 `/admin/providers`，通过本机 Supabase Auth 登录；表单调用本分支的 Next Server Actions 和 SQL。测试库独立启用了 #385 的 v2 目录。OpenRouter 公开目录和 Seedream 端点报价取自当日只读 GET，在测试端重放；503、空参数和缺报价为故障模拟。

预览历史记录另作只读核对。该模型 14 次后台生成和 1 次用户生成均为成功 1K；每条记录的供应商回传 `usage.cost` 为 **$0.018**，站内 `cost_usd` 为 **$0.01899**（含 5.5% 充值费分摊），与现行公示报价吻合。旧记录没有 OpenRouter generation ID，无法逐笔关联外部账单；没有 2K 账单样本。测试未触发生成、实际扣款或生产写入。供应商测试密钥仅用于验证保存与读取；新请求的生成效果、质量档及下一笔真实账单均未验证。

**四项留空时的区别。** 原来「每百万 token 输入、输出」与「1K、2K 单张估价」均留空，只要上游回了费用仍会记账；但模板端在无足量实测时拿不到安全底线。现在 Seedream 直接按 Images 端点的真实单位展示（不是百万 token 价），两个可用档均可自动估价。按 token、按面积或多端点计价不能完整折算时保留未知；若有模型/档位实测 p95 或手工估价，仍按既有优先级取用。密钥不会随公开报价查询发出。公开来源：[Images 目录](https://openrouter.ai/api/v1/images/models)、[Seedream 图片端点](https://openrouter.ai/api/v1/images/models/bytedance-seed/seedream-5-0-flash/endpoints)。

**新调用如何入账（受控测试）。** 正式生成与后台试跑共用结算。成功、上游报告失败、解码/存储失败都保留可取得的原始金额。已提交但未获回执时记录待核；没发出生成请求则不会伪造供应商用量。供应商给出 generation ID 且缺金额或 BYOK 标识时，用同一接口根地址和密钥做一次有时限的免费 [generation 查询](https://openrouter.ai/docs/api/api-reference/generations/get-generation)，校对返回 ID；查不到则保留 ID 供后续核查。此 GET 在出图超时计时器之外，不因查不到费用而丢弃已生成图片。

- 已确认非 BYOK：原始回执金额保存在 provider_usage；站内成本按项目约定分摊 Standard 充值费用（乘 1.055）。充值费不是这次生成的供应商账单行。[OpenRouter 计费说明](https://openrouter.ai/pricing)
- BYOK 或未确认是否 BYOK：保留已知的 OpenRouter 收费与上游参考金额；不能证明外部供应商最终收款，总成本待核。没有回执时若能按 token 完整估算，只另存估算，不计入实收；试跑预算与实际成本分列。未补写任何历史记录。
